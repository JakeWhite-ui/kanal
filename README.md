# Дашборд канала · путь к 100 000 AED

Личный журнал и статистика по Telegram-каналу и Threads. **Приватный репо** — внутри суммы поступлений и процент к цели.

## Запуск

```
node server.js
```
→ http://localhost:4320 · порт занят только этим проектом.

Зависимостей нет. Нужен только Node.

## Где живут данные

`data.json` в этом репо — единственный источник правды. Сервер пишет его целиком при каждом изменении (через временный файл, так что обрыв не оставит битый JSON).

**Это сделано ради синка между двумя Mac.** localStorage не ездит через git — файл ездит. Порядок тот же, что с Obsidian:

```
git pull  →  правишь в дашборде  →  git add -A && git commit && git push
```

Пропустил pull перед правкой — два Mac разъехались, и чинить придётся руками.

## Что где

| Вкладка | Для чего |
|---|---|
| **Цель** | Процент к 100 000, сколько осталось, нужный темп в день против фактического, прогноз на 31.12. Поступления строками |
| **Канал** | Подписчики по снимкам + спарклайн, лог вышедших постов с рубрикой и просмотрами |
| **Журнал** | День за днём: что сделано, сколько минут, провал дня |
| **План** | Задачи по группам со весом 1–3. Процент закрытого считается по весу, а не по количеству |

## Правила, на которых это держится

- **Провал дня заполнять.** Журнал без провалов через месяц станет бесполезным — по нему нельзя будет понять, что ломалось.
- **Снимок подписчиков раз в неделю, в один и тот же день.** Иначе прирост не с чем сравнивать.
- **Ни одно число не предзаполнено.** Каждое поступление вносится с источником, чтобы цифру в публичном отчёте можно было проследить.

## Файлы

```
app.js       без ES-модулей: ?v= на <script src> не бустит импорты внутри модуля
data.json    источник правды
```

Кэш-бастер `?v=N` на `app.css` и `app.js` поднимать при каждой правке.
